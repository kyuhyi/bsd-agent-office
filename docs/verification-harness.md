# 구현 전 검증 하네스 설계

현재 상태: 검증 설계만 작성. 테스트 러너 설치, 테스트 실행, 구현은 아직 하지 않았다.

## 우선 수직 시나리오
새 테스트 프로젝트에서 ‘README 내용을 읽고 개선 계획을 제안해 줘’를 실행한다. 파일 변경 없이 실제 Claude/Codex 결과를 받고 직원의 작업 상태와 결과 패널이 일치하는지 확인한다. 두 제공자는 각각 따로 검증한다.

## 테스트 → 구현 → 검증
| 경계 | 먼저 실패시킬 테스트 | 구현 후 증거 |
|---|---|---|
| 업무 상태 | 성공/실패/취소 상태 혼동 및 종료 후 이벤트 처리 | 상태 전이 단위 테스트 |
| 제공자 파서 | 잘린 JSONL, 여러 줄, stderr, 도구 거절, 비정상 종료 | 고정된 정제 이벤트 fixture 테스트 |
| 권한 | 작업 루트 탈출·허가 없는 덮어쓰기·삭제 거절 | 실행 전 검증 및 사용자 승인 흐름 |
| 동시 실행 | 동일 작업 공간 쓰기 두 건 요청 | 잠금/큐 테스트 |

| 취소 | 사용자가 중지한 이후 실행기와 자식 프로세스 잔존 | Windows 프로세스 종료 통합 검증 |
| 캐릭터 | 장애물 관통, 좌석 중복, 프레임 속도에 따른 이동 차이 | 경로/좌석 단위 테스트와 실제 화면 확인 |
| 실제 연결 | 로그인 실패·사용량 제한·시간 초과 | 실패 이유 표시와 재시도 흐름 |
| 결과 | 결과 없는 성공 표시 | 결과 파일/텍스트 및 검수 증거 연결 |
| 비밀 정보 | 인증값 형태가 포함된 이벤트 fixture | 정제 전후 로그와 UI 노출 검사 |

## 화면과 성능 검증 목표
- 데스크톱 1440×900, 모바일 390×844에서 지시·직원 선택·결과 확인 가능.
- 목표 기기와 브라우저를 기록하고 30초 구간의 프레임 시간을 측정한다.
- 데스크톱 목표 60fps, 저사양/모바일 목표 30fps. 목표일 뿐 측정 전 통과라고 기록하지 않는다.
- 이동 감속, 방향 전환, 발 미끄러짐, 의자 정렬, 캐릭터 가림을 영상으로 검토한다.
- 모션 감소 설정, WebGL 실패 시 업무 목록 대체 화면, 키보드로 주요 조작 지원.
- 장시간 로그는 페이지 분할/가상화하고 사무실의 프레임 갱신과 분리한다.
