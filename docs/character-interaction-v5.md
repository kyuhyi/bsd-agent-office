# 캐릭터 직접 조작

요청: 대표의 일어나기·걷기·착석, 전 캐릭터 클릭 메뉴, 질문·업무 지시·바닥 이동·자리 복귀.

구조: OfficeApp의 선택/명령 → 캐릭터별 이동 상태 → 기존 가구 장애물 경로 탐색. 대화와 업무는 기존 로컬 인증·CLI 큐를 사용하며 화면 이동과 실행 결과를 분리한다. 대표는 사용자 아바타이므로 팀원 선택 후 질문/지시한다.

검증: 구현 전 목적지·가구 충돌·전원 왕복 경로 테스트. 이후 실제 대표 리깅의 서기/앉기 혼합, 브라우저 메뉴·이동·복귀·대화 입력·업무 입력과 기존 회귀 테스트를 확인한다. 브라우저 시험으로 실제 유료 CLI 업무를 자동 제출하지 않는다.

## 반영 내용
- 캐릭터 몸체와 이름표 클릭 → 대화하기 / 업무 지시 / 이동하기 / 자리로 복귀. 대표는 화면 왼쪽 아래 바로가기에서도 선택한다.
- 대표의 원본 24관절 리깅을 보존하고 서 있는 자세와 앉은 자세를 혼합한다. 이동 거리에 맞춰 팔·다리의 보행 주기를 조절한다.
- 이동하기 → 바닥 지정. 가구·화단과 사무실 경계를 검사한다. 수동 이동 뒤에는 목적지에 서 있으며 자동 산책으로 덮어쓰지 않는다. 복귀하면 자기 의자에 앉는다.
- 목적지 지정 중에는 인물과 카메라를 잠시 고정하고 Esc/취소로 빠져나올 수 있다. 업무 실행은 시각적 이동과 별개다.
- 질문은 선택 직원의 실제 Claude/Codex 큐에 분석 요청으로 들어간다. SSE로 진행·응답을 표시하고 완료된 직전 대화를 참고한다. 대표는 사용자 아바타이며 질문/지시는 담당 팀원을 골라 전달한다.
- 질문과 업무 초안을 분리한다. 전송 전에는 실행하지 않으며 로그인·연결 상태를 확인한다.

## 검증 및 경계
- 백업: `output/before-character-interactions-v5.zip`.
- 회귀 테스트 30개 통과. 전원 수동 왕복, 가구 충돌, 대표 실제 리깅 자세 혼합, 직원/제공자 요청 전달과 대화 연결 검사 포함.
- 개발 브라우저에서 대표 몸체 클릭, 메뉴, 실제 이동 후 서기, 대표석 복귀·착석, 직원 이동, 질문·업무 입력창과 전송 활성화를 확인했다.
- 추가 생성 크레딧 0. 이번 검증에서 새 실제 CLI 요청은 제출하지 않았다.
- 이동 상태는 브라우저 세션에만 유지된다. 새로고침하면 원래 자리로 돌아간다. 기존 실행기는 별도 결과물 폴더를 사용하며 프로젝트 원본을 자동 수정하지 않는다.
- 최종 실행용 빌드와 HTTP 200 확인. 브라우저에서 대표와 소라의 수동 이동 후 대기 및 원래 좌석 복귀·착석을 재확인했다. 대표의 직원 선택 시 실행 제공자가 해당 직원의 Claude/Codex로 전환되고 질문·업무 초안이 분리되는 것을 확인했다.
- 결과 화면 `output/office-interactions-v5.png`, 브라우저 검증 기록 `output/office-interactions-v5-verification.json`.
