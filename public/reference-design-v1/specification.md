## 결정과 우선순위

사용자가 선택한 개인용 실제 Claude Code·Codex 실행 / 고급 실제 3D / 귀여운 캐릭터를 유지한다. 최신 첨부 `codex-clipboard-1dfbb87f-05ee-43ff-9700-a73f117ee932.png`의 구도와 외관을 유일한 시각 기준으로 사용한다. 새로운 스타일이나 임의의 방 배치를 제안하지 않는다. 기존 `premium-scene-passport.md`와 `architecture-proposal.md`의 비주얼 제안보다 이 문서를 우선한다. 기존 문서는 작업 이력으로 보존한다.

원본은 1024×572. 한 장의 이미지로 제작 도구·실제 3D 여부·정확한 치수를 확정할 수 없다. 아래 위치는 화면에서 판독한 근사 앵커이며 실제 미터 치수가 아니다. 보이지 않는 면은 제작 단계에서 보완한다.

## 카메라와 UI

- 기본 화면: 직교 카메라 또는 아주 약한 원근. 화면 앵커를 맞추는 카메라 보정이 우선이다. 최초 높이각 30–35°, 좌우 각도 40–45°는 시작값일 뿐 확정치가 아니다.
- 바닥, 창 꼭짓점, 회의 탁자, 리셉션, 개발 A의 5개 앵커로 투영을 보정한다. 각 중심 오차를 화면 대각선의 2% 이하로 줄인다. 오차 수치만으로 외관 합격 처리하지 않는다.
- 원본 기준 상단바 31px. 하단 명령 바는 y=543부터 약 29px, 가로 약 634px. 1440px 이상 화면에서는 각각 40–44px, 40–44px까지 키워 가독성을 확보한다.
- 처음에는 얇은 명령 바만 보이고 업무 지시를 누르면 입력창을 확장한다. 보고·결재·실시간·회의·비서 브리핑은 요청 시 서랍으로 연다. 사무실 중앙을 상시 패널로 가리지 않는다.
- 팀 필터는 오른쪽 위. 회전·확대 버튼은 부차적 도구로 숨긴다. 기본 시점 복귀를 항상 제공한다.
- 1024×572에서 페이지 세로 스크롤이 없어야 한다. 기존 680px 최소 높이를 사용하지 않는다.
- 좁은 화면에서는 같은 공간의 팬·확대를 제공하며 UI는 하단 시트로 전환한다. 큰 화면과 같은 전체실 가독성을 보장한다고 주장하지 않는다.
- 연결·업무 수는 서버의 실제 상태를 사용한다. 원본의 93% 등 예시 수치를 복제하지 않는다.

## 캐릭터 계약

KYU는 원본 스프라이트를 외형 기준으로 사용하되 2D 스프라이트를 3D라고 부르지 않는다. 정면·측면·후면 시트를 먼저 대조하고 메시·리그·재질을 별도로 제작한다. 머리 비율, 모자 챙, 검은 뿔테, 데님, 흰 운동화, 키링을 보존한다. 직원 6명도 같은 눈·피부·머리카락·팔다리 스타일로 통일한다.

필수 클립: idle / turn / walk / stop / sit_down / seated_idle / type / read / stand_up / talk / wave. 모든 클립은 같은 리그를 사용하며 시간 기반으로 블렌딩한다. 이동 속도와 발걸음 주기를 맞추고 발 접지, 손의 키보드 위치, 의자 정렬, 치마·바지 관통을 확인한다. 앉은 캐릭터 전체를 위아래로 흔드는 대체 동작은 허용하지 않는다.

좌석마다 approach·stand·seat·desk·lookAt 앵커를 둔다. 통로 경로와 좌석 예약을 분리한다. 30초 시연은 대기→회전→걷기→감속→착석→타이핑→일어서기→회의 좌석 이동을 한 번에 검증한다. 정지 설정은 모든 비필수 동작을 멈추되 올바른 자세를 유지한다.

## 제작 및 실행 구조

```text
원본 이미지 + BSD 로고 + KYU 시트
  → 구도 앵커·가구 목록·시트 규격 (이 설계)
  → Higgsfield의 지원되는 자산/시트 제작·검토
  → Blender 공간 모델링·UV·PBR·조명 베이크 / 캐릭터 리깅·동작
  → GLB + 텍스처 + 좌석·통로·선택 앵커
  → Three.js 공간 + AnimationMixer 캐릭터 + 독립된 업무 패널
  ← 기존 로컬 서버 / SQLite / SSE ← 실제 Claude Code·Codex CLI
```

이미지 생성 결과는 콘셉트·텍스처 입력이며 자동으로 리깅된 3D 모델이 되지 않는다. Higgsfield의 실제 출력 형식과 지원 기능을 확인한 뒤 다음 공정에 넣는다. 이전 실험 씬은 보존하되 승인된 최종 아트로 취급하지 않는다.

제안 파일 경계: `features/office/scene/`(환경·카메라·조명), `features/office/layout/`(가구·좌석·통로 앵커), `features/characters/rig/`(리그·클립), `features/characters/behavior/`(이동·착석), `features/office/hud/`(바·서랍). 자산 매니페스트에 버전·출처·단위·폴리곤 수·텍스처 크기·리그 이름을 기록한다. 같은 좌석 데이터에서 화면 선택·캐릭터 목적지·장애물을 유도해 좌표 복제를 피한다.

기존 실행기는 계속 사용한다. 현재 검증된 실제 실행 범위는 선택한 프로젝트의 제한된 스냅샷을 읽어 새 결과물을 생성하고 반대 제공자가 검수하는 흐름이다. 기존 저장소 자유 수정·터미널 테스트 자동 실행까지 구현됐다고 표시하지 않는다. 캐릭터의 이동 완료는 업무 성공 이벤트를 만들 수 없다.

## 하네스: 순서를 지키는 통과 조건

1. 구도: 1024×572 기본 화면, 무패널, 야경, 동일 스케일로 원본과 나란히 비교. 15개 앵커·5개 업무 벤치·중앙 회의 공간·좌측 오락 공간이 맞아야 다음 단계로 진행.
2. 아트: 원본과 전체/라운지/업무석/캐릭터 확대 비교. 밝은 바닥·빈 배경·고무 같은 가구·블록 인물은 P1 실패. 색·명암·소품 밀도·접촉 그림자를 함께 판정.
3. 리그: 위 30초 동작, 발 미끄러짐·의자/탁자 관통·갑작스러운 순간이동·좌석 중복 0건. 동작 감소 설정도 검증.
4. 성능: 측정 기기·뷰포트·브라우저를 기록하고 30초 동안 목표 45fps 이상, 하위 1% 30fps 이상을 확인. 이 수치는 목표이며 현재 측정값이 아니다. 미달 시 인스턴싱·LOD·그림자·텍스처 최적화.
5. 실제 운영 회귀: 지시→실행 상태→결과→교차 검수, 실패·취소·재접속. 허위 연결/사용량/완료 상태 0건.
6. 최종: 원본/새 캡처/차이 목록을 함께 남긴다. 기능 테스트 통과가 외관 검증 통과를 대신하지 않는다. P1/P2가 남으면 완료로 표시하지 않는다.

우선 제작 단위는 **원본 구도의 공간 전체 + 개발 A 한 벤치 + KYU 한 캐릭터**다. 구도가 맞지 않은 상태에서 여러 직원·소품·연출을 확대하지 않는다. 이 단위의 외관 및 동작이 통과한 후 같은 자산 체계로 전체 공간을 완성한다.
